# 论文讲解与组会读稿

让读者跟着论文走，读到哪里就理解到哪里。先核对论文正文、图表、图注和补充材料的实际内容，再写中文读稿。研究对象、方法操作、关键数字和结论都应能定位到原文；解释可以比原文更易懂，但不能把自己的推断冒充作者已做的实验。

## 起点与覆盖

确认论文版本、目标读者、用户要整篇还是指定范围，以及 Markdown、PDF 等交付形式。按论文的实际标题与顺序列出章节、核心图表和补充材料中的关键协议。正文以引言、方法、结果、讨论为主线；如论文把方法放在结果之后，为了让读者读懂结果，可先讲方法，再说明原文位置。不要只凭摘要或图 1 概括整篇。

内部建立简短覆盖表：每个章节和关键图表对应研究问题、实际方法、主要观察、关键数字和原文位置。正文不展示机械清单，也不增设“先读懂一句话结论”“术语速查”“容易误读”“复习路径”等固定栏目。原文中支撑主要发现的内容不能因篇幅而略去；对读者不重要的细枝末节可压缩，但方法中会改变数据、模型或比较的设置要保留。

## 沿原文解释

引言交代研究对象、已有做法、具体困难、作者提出的问题和本文路线。遇到陌生概念，给中文译名、英文全称及一句说明：它是什么、在本研究中做什么。不要把多个新名字先堆成术语表，再让读者回头找。

方法按实际实施链写清：输入是什么、从哪里来、怎样选取和准备、经过哪些处理、每一步的关键参数或筛选规则、产生什么中间物、怎样流向下一步、最后用什么验证。原文只给名称时，查正文、图注及补充材料能否补足；确实未说明的设置只在影响理解的位置说明缺口。软件首次出现时，用短括号交代用途；数字首次出现时紧接说明分母、计数对象、计算方式或设置来源。

若有流程图或架构图，另做一版围绕图逐项讲解的方法说明：顺着箭头讲每个框的输入、处理、输出和去向，解释分支为何分开、在哪里汇合、哪些参数共享、哪些头或损失只在某阶段使用。图外的实施细节和协议穿插到对应框或箭头处；不要把读者需要连起来理解的“概念、操作、配置、流向”拆成四个相隔很远的清单。

结果跟原文的实验顺序走。每个结果单元就近写明实验设置、比较对象、指标和图的读法，再解释图中观察到的趋势、例外及作者由此得出的结论。只服务于该实验的模拟协议可放在相应结果前；模型构建和训练主方法仍集中在方法章节。讨论区分实际观察、作者解释与进一步推断，限制只在会影响该结论处说清，不逐段重复否定句。

## 术语、公式、数字与图

缩写首次出现时尽量给英文全称、中文译名和作用；名称不是缩写时不要编英文展开。专有名词若中文译名仍陌生，再用一句普通话解释。例如“周期性边界条件（把模拟盒在空间中重复，用有限盒近似体相环境）”。复杂概念先说动作和对象，再给术语。

公式先说明它回答什么问题，再解释每个符号、量纲、求和或平均对象，以及参数变化会带来什么结果。数学式应使用目标 Markdown/PDF 渲染器支持的写法；生成后检查希腊字母、上下标、粗体与括号。计算式如 `20×19×18` 要说明每个因子代表的选择及为什么递减。术语、公式、示意图和解释放在相邻位置，不要求读者跨章节查找。

图表在首次讨论处放置或就近引用。先说明图的输入和轴、颜色、图例、单位、分母及误差，再按分面解释实际观察。模型架构图要讲数据和梯度怎样流动；流程图要讲物料或构型怎样变化；结果图要说明比较条件与读数。图中未给出的实施细节可依据正文或补充材料补充，并标出来源。不得用概念性复述替代图中每个关键部件的具体作用。

对论文没有回答、但读者很可能会追问的关键细节，先检查正文、图注和补充材料。查到就原地补上；查不到时用简短具体的话说明缺口，例如“文中给出了总构型数，但未列出逐离子水合数”。不要额外写一串“不能据此证明……”式推测。

## 表达与成品

每段围绕一个问题或步骤，句与句交代因果与承接；从上一段的输出自然进入下一段的输入。先说准确的正面陈述，必要条件在其影响读法的位置说一次。删空泛评价、假想反驳和重复防御性措辞。加粗只圈住需要强调的词句，不把 Markdown 标记与括号拆开造成渲染错误。

需要成品时，交付一份可独立阅读的 Markdown；用户要求 PDF 时由同一份 Markdown 导出。检查标题、图文邻接、图片路径、公式、分页与中文字体的实际渲染。出处用论文页码、章节、图号或补充材料位置就近标记。最后核对覆盖表，确认没有遗漏支撑主要结论的方法、结果和图表。
