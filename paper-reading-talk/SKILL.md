# 论文组会读稿：方法讲透、出处可查

## 核心写法

读稿先看清**这篇论文实际讲了什么**，再按用户讲述需要组织。用户当前偏好的组会主线是“引言 → 方法 → 结果 → 讨论”，其中**方法是重点**：讲清输入、表示、算法/公式、参数、步骤间依赖与验证设置，再让结果回答方法是否奏效。论文若把 Methods 排在 Results 后，讲稿可以把那些方法细节提前，但必须标明原文所在章节与 PDF 页码；不能把原文 Results 的内容误说成 Methods，也不能因重排漏掉论证。摘要可在最前面简述，但不能代替正文。

在每一节内尽量保持该主题在原文中的论证顺序。读到陌生术语、缩写、公式、操作或结果图时，**就在这里停下解释**它是什么、为什么需要、各部分怎样连接、如何读或计算；解释完继续该主题。不要预先堆一章背景，也不要把解释挪到文末速查表。用户范稿中的原句摘录、中文释义、追问和直观例子，都是这种局部讲解方式。

若用户要求额外的“图导向方法版”，保留现有读稿，另建同源论文的独立版本。引言、结果和讨论仍覆盖原文；方法按论文中真正承载流程的图或架构图展开，不把图当作开场装饰。该版不是把原图标签翻译一遍，而是让读者能沿箭头复述数据、表示、模型、训练、输出与验证怎样连接。

## 图导向方法版

用户要求围绕流程图或架构图逐项讲方法时，先完成上面的原文覆盖，再读取 [图导向方法细则](references/figure-guided-method.md)。按图中箭头把输入、筛选、处理、设置、输出、训练和验证连成操作链；与图相关的正文、图注和补充材料信息放在对应步骤旁。普通读稿也要讲清核心方法，但不必加载只服务于图导向版本的详细检查。

## 动笔前的覆盖检查

1. 确认论文版本、正文与补充材料范围、PDF 页码和图号；先看用户的范稿如何讲段落、公式与图，而不把范稿中的科学判断直接当事实。
2. 在工作笔记里按原文章节逐段记录：该段提出的事实或论点、关键数字及单位、公式、图表、与前后段的承接。写完逐项对照。目标是让原文**重要内容和论证转折**在读稿中都能找到，而非每句翻译或只摘几条摘要。常规文献铺垫可合并，但不能跳过参数来源、旧方法局限、作者为何选此改动、反例及边界。
3. 先准确翻译原文标题，再决定讲稿结构；区分“原文顺序”与“讲述顺序”，不得声称二者相同。方法移到结果前时，把原文 Results 中的选样、计算和拟合步骤与文末 Methods 的实施细节合并讲透，同时避免结果段重复。不要自动添加“先读懂一句话结论”“组会开场建议”“术语与缩写速查”“容易误读的地方”“用来复习的理解路径”“组会结尾可以这样讲”等框架栏目。
4. 对每个原文章节、主要图表、补充材料中支撑正文主张的实验建立覆盖清单；每项记录其论点、方法、关键条件、结果、限制及在读稿中的位置。省略某项需能说明它为何不影响理解，不能用“篇幅有限”跳过核心协议或反例。正文与补充材料互相矛盾时，标出两处位置及冲突内容，不替作者暗中消歧；必要时说明需要归档配置或原始数据核验。

## 原地解释与证据

- 术语和缩写首次出现时给出全英文、中文、字母含义及在本文中的作用；不是缩写的名称说明其来源。只解释当前论证需要的深度，后文需要更多细节时再补。`GPU-days` 等计算资源单位和其他非日常单位也要在首次出现处解释计量方式，必要时给一个简单换算例子；后文直接使用，不把解释拖到汇总段。
- 对“周期环境”“体相”“等变”“偏置窗口”等决定方法理解的概念，首次出现时还要用一两句讲清它**具体如何运作、解决前一步的什么问题**，必要时给一个贴近该论文对象的简单例子。只写中文译名或抽象定义仍不足以让读者接上下一步；解释完应接回当前输入和流程。
- 软件、数据库和算法第一次出现时，在执行该步骤的句子旁用一小句解释“它在本文接收什么、做什么、交给谁”；不要另列工具名词表。数字来自枚举、浓度换算、窗口数或筛选时，写出计算关系和计数规则，例如序列位置是否有顺序、是否允许重复、端点是否计入。遇到“选定、截取、过滤、挑选、抽样”，核对原文是否给出选择标准、半径或阈值、样本来源和输出数量；有则讲操作，没有则明确指出原文在哪一步没有给出规则，不能用一个动词掩盖复现缺口。
- 段首提示词使用加粗时，让 `**` 在中文冒号前闭合，例如 `**输入**：`；冒号及后面的解释保持普通字重。不要把整句动作和句号一起放进加粗标记。
- 中英对照的图中模块名也只加粗中文，英文括号放在加粗标记外，例如 `**中程等变模块**（Medium-range Equivariant Block）`、`**共享骨架**（Shared Backbone）`。不要写成 `**中文（English）**`；交付前用实际 Markdown 和 PDF 渲染检查这类标记。
- 原文公式尽量按原记号呈现；紧接着说明每个量、单位、求和范围、项的物理或统计意义，以及公式为什么出现在这里。若为帮助理解另写简化式，明确标“示意式”，不能混称原文公式，也不要无依据添项或漏掉系数。
- 图或表放在首次讨论它的段落旁。逐面板说明坐标、图例、比较对象、数值方向、可直接观察到的现象，再讲作者解释和能够支持的结论。PDF 排版时检查图与解读是否被拆到两页。原图若可合规使用，保留原图信息与出处；无法插图时给精确原文页码，不能把页码提示当作图解。
- 对分子或其他空间结构，若后续结果依赖“哪个原子、残基或部位”，在首次讲到该结构时就近放能定位这些部位的原图或可靠示意；说明它是完整体系、截取片段还是模型，标号与后续曲线一致。图像仅有编号而无法定位时，补清楚位置关系，不让读者靠文字猜。
- 结果图按“本图回答的问题与主要发现 → 图及简洁图注 → 紧接的中文逐面板分析”组织；图后至少解释实际看到的趋势、例外和能支持的范围，不能把解释全放图前或把多张图堆到文末。指标首次用于判断时说明测量对象、单位、符号方向、参考对象及误差条含义；只有比较目标明确时才称“更好”。
- 区分论文数据、作者解释、帮助理解的类比和自己的推断；通常用自然语言在相应句子中说清，不强制设置标签栏目。用户范稿中形象但过强的因果、速度、精度或物理断言应回原文核验，必要时限定或纠正。引用原句保持短，主体用自己的话解释。
- 全文用直接陈述讲原文做了什么、得到什么。解释术语时讲它在当前步骤中实际指什么、起什么作用，然后继续论文主线。避免追加读者未提出的排除句，例如“这里的无偏不代表初始构型没有选择”。若限制会改变结果解释，在相关方法或结果处写出具体条件和影响。交付前检查“不是／不代表／不能／并非”等句式，删去无信息增量的辩解，将必要的科学界限改为正面、具体的陈述。
- 数字交代体系、条件、单位、指标和比较基线。拟合误差不等于实验构象正确；短轨迹保持结构不等于平衡自由能准确。正面结果、负对照、失败体系和作者承认的局限同样要写，不能为了故事流畅删掉反例。
- 每个核心方法讲到读者能够复述操作链：输入与来源、预处理、计算或训练步骤、公式中的门槛和权重、输出、与其他步骤的依赖，以及验证协议。多场景模拟逐一交代建模、预平衡、生产条件、对照之间不一致处、控制实验、观测量和不确定性；不能把十几页方法压成通用的“做了 MD/采样”。有未给出的设置时直说未给，不补造。
- 对照实验核查“相同”的具体范围：体系、起点、时间步、约束、恒温恒压方式、势函数、取样长度和分析方法是否一致。若不一致，先说明差异及作者的控制，再解释结果。把独立重复与同一轨迹的时间帧区分开；bootstrap 范围、重复间标准差和置信区间不得互称。
- 拆开模型拟合老师、不同理论层级复算、与实验比对三个证据层次。计算性能须同时写硬件、体系、是否实测或插值、显存、单步与总时长口径；“可运行”不能自动推成“高效”。资料公开时区分完整语料、开放子集、权重与脚本的实际范围。
- 可追溯的技术细节保留在工作底稿；面向组会的正文只放帮助理解论证的来源页码、图表编号和关键条件。若用户另要复现或审计材料，再集中列代码、配置、运行身份等证据，不让路径和哈希打断论文讲述。

## 成品与迭代

用户要求 Markdown 和 PDF 时，从同一份 Markdown 导出，检查中文字体、公式、图注、图文邻接、分页及缺页。保留用户原稿，不覆盖其 Read.md/Report.md；只更新本次授权的成品。若用户指出某节缺点，先与原文逐段比对，修正 Skill 中导致遗漏的规则，再回到成品重写并重新导出。

交付前做一次独立于写作的对照审读：逐项检查覆盖清单、数值与单位、原文内部冲突、解释是否让陌生读者理解“为什么”和“怎样”，以及每张图的关键面板是否在邻近正文得到中文解读。检查实际渲染页面，裁去原页边和无关长图注；只统计图片数量和公式无报错不算图文验收。

本 Skill 管论文内容覆盖、出处核对与组会讲述顺序；需要独立教材时再用 `concept-reconstruction`，不能把论文读稿改造成脱离原文的知识点合集。
